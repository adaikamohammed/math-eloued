## 1. عطل تكرار مفاتيح React في محفظة الأساتذة (Encountered two children with the same key)
- **الأثر:** ظهور تحذير أحمر في بيئة Next.js / Turbopack بسبب تكرار المفتاح `prof-vqnexp`.
- **السبب:** كان الكود يعتمد على `key={teacher.slug || teacher.code}`، وعند حفظ نفس الأستاذ لأكثر من ابن، يتطابق الـ `slug` أو الـ `code` في بطاقتين مختلفتين في المصفوفة.
- **الحل الجذري:** اعتماد مفتاح مركب فريد مع إضافة مؤشر المصفوفة:
  ```tsx
  key={`${teacher.slug || teacher.code || "teacher"}-${index}`}
  ```

## 2. خطأ تشفير Base64url في محفظة العائلة (Unknown encoding: base64url)
- **الأثر:** حدوث `Runtime TypeError: Unknown encoding: base64url` عند محاولة توليد رابط مشاركة المحفظة العائلية للأولياء.
- **السبب:** استدعاء `Buffer.from(str, "utf-8").toString("base64url")` في بيئة متصفح أو حزم Node مجتزأة لا تدعم معيار `base64url` بشكل افتراضي.
- **الحل الجذري:** كتابة دالة تشفير Base64url قياسية ونظيفة 100% تعمل دون الاعتماد على `Buffer`:
  ```typescript
  export function toBase64Url(str: string): string {
    const bytes = new TextEncoder().encode(str);
    let bin = "";
    for (let i = 0; i < bytes.length; i++) {
      bin += String.fromCharCode(bytes[i]);
    }
    return btoa(bin)
      .replace(/\+/g, "-")
      .replace(/\//g, "_")
      .replace(/=+$/, "");
  }
  ```

## 3. معضلة شاشة الأوفلاين عند تسجيل الدخول أو إنشاء الحساب (Offline Mode Trap)
- **الأثر:** ظهور رسالة "وضع العمل بدون إنترنت (أوفلاين) - منصة جسور التعليمية" للأستاذ عند محاولة تسجيل الدخول أو الضغط على "انضمام كأستاذ" بالرغم من توفر اتصال إنترنت سريع ونشط.
- **الأسباب الجذرية العميقة:**
  1. **اعتراض طلبات التنقل (Navigate Requests):** كان ملف `sw.js` يلتقط كل طلبات التصفح (`req.mode === "navigate"`).
  2. **إلغاء الطلب من قِبل Next.js:** عند استدعاء `router.push("/admin")` يليه `router.refresh()` في نفس اللحظة، يقوم راوتر Next.js بإلغاء الطلب الأول تلقائياً (`AbortError`)، فيظن الـ Service Worker أن الاتصال انقطع ويقدم صفحة الأوفلاين المخزنة في الكاش.
  3. **استمرار تشغيل الـ Service Worker القديم في المتصفح:** متصفحات الهواتف والحواسيب تحتفظ بالـ Service Worker القديم ولا تلغيه بمجرد تحديث الكود على السيرفر إلا بإلغاء تسجيله برمجياً وحذف كاش `jusoor-offline-v1`.
  4. **كاش الخلفية التلقائي:** كان ملف `OfflineIndicator.tsx` يقوم تلقائياً بفتح الكاش القديم وتخزين صفحة `/offline` فيه.
- **الحل الشامل والنهائي:**
  1. **إلغاء وتطهير الـ Service Worker ذاتياً (`public/sw.js`):** تحويل ملف `sw.js` إلى سكربت تطهير ذاتي يقوم بحذف كل الكاش القديم وإلغاء تسجيل نفسه فوراً وعدم اعتراض أي طلب شبكة إطلاقاً.
  2. **تنظيف متصفح العميل تلقائياً (`ServiceWorkerRegister.tsx`):** استدعاء `navigator.serviceWorker.getRegistrations()` وإلغاء أي تسجيل سابق، مع مسح `caches.keys()`.
  3. **تجريد `OfflineIndicator.tsx`:** حذف كود التخزين المؤقت الخلفي نهائياً لمنع تخزين صفحة الأوفلاين مجدداً.
  4. **تحديث ذكي لصفحة `/offline`:** تحويلها لصفحة تنظيف فوري تنقل المستخدم المتصل تلقائياً إلى صفحة الدخول مع زر فوري لتحديث الذاكرة.
  5. **توجيه آمن ومباشر بعد تسجيل الدخول وإنشاء الحساب:** استخدام `window.location.href = "/admin"` لضمان انتقال كامل ونظيف للوحة التحكم دون أي تعليق أو أخطاء إلغاء.
